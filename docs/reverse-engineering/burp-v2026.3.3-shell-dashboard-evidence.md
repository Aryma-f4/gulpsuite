## Verification on this worktree

- `cargo test --all-targets --quiet`: passed (356 library tests plus integration and 10 UI parity tests).
- `cargo test --test ui_parity --quiet` without snapshot update mode: passed; both approved 1440×790 PNGs matched.
- `cargo build --release --bin gulpsuite --quiet`: passed; the release binary opened a native macOS window.
- `cargo clippy --all-targets --quiet`: exited successfully with existing repository warnings. This parity slice did not turn unrelated warnings into a cleanup task.
- `cargo fmt --check`: failed because the repository already has thousands of unformatted lines in unrelated files. The newly created UI parity test and WIP module were formatted individually; `git diff --check` passed.

Snapshot comparison uses `egui_kittest::SnapshotOptions` with threshold `0.6` and an allowance of 10 changed pixels per OS. Version 0.33.3 does not read a `kittest.toml`, so the effective configuration lives in the test code rather than an inert file. Fixture data is deterministic: two seeded live tasks, one completed scan, four severity levels, three event levels, and a fixed memory label.

## Remaining differences and unknowns

The shell/Dashboard is a functional parity foundation, not an almost-100% clone of Burp. The original Burp screenshot was inspected live but is not redistributed in this repository. A strict visual difference score was not computed across applications because their native window chrome, scaling, font rasterization, and available runtime data differ. New scan currently starts the existing scanner configuration directly; Burp's full scan-setup flow is not reproduced. Scanner cancellation updates task/UI state, but the active worker can continue until its current network operation finishes. Live native detach/reattach and narrow-window behavior need a cross-platform manual pass. BApp Store and AI are WIP as requested. All other Burp tools remain separate future parity slices.
