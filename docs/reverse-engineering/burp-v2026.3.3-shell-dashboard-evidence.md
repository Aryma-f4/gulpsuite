## Verification on this worktree

- `CARGO_PROFILE_DEV_DEBUG=0 CARGO_INCREMENTAL=0 cargo test --quiet`: passed after the final local-tool corrections: 360 unit tests and 70 integration/UI tests, including 17 UI parity tests (430 total). Disk exhaustion during earlier builds was addressed by cleaning regenerable debug artifacts; source files and the original app were preserved.
- `cargo test --test ui_parity` without snapshot update mode: passed; all three approved 1440×790 PNGs matched.
- `cargo build --release --quiet`: passed after the final corrections. `Gulpsuite-preview.app` was assembled, ad-hoc signature and plist verified, and launched natively. The existing `Gulpsuite.app` bundle was not overwritten.
- `cargo clippy --all-targets --quiet`: exited successfully with existing repository warnings. This parity slice did not turn unrelated warnings into a cleanup task.
- `cargo fmt --check`: failed because the repository already has thousands of unformatted lines in unrelated files. The newly created UI parity test and WIP module were formatted individually; `git diff --check` passed.

Snapshot comparison uses `egui_kittest::SnapshotOptions` with threshold `0.6` and an allowance of 10 changed pixels per OS. Version 0.33.3 does not read a `kittest.toml`, so the effective configuration lives in the test code rather than an inert file. `gulpsuite-dashboard-empty-light.png` uses two seeded tasks, no issues/events, and fixed memory text. It is a Gulpsuite regression render, not a Burp screenshot or cross-application pixel comparison. The other fixture adds one completed scan, four severity levels, and three event levels to exercise populated states.

## Remaining differences and unknowns

The shell/Dashboard is a functional parity foundation, not an almost-100% clone of Burp. The original Burp screenshot was inspected live but is not redistributed in this repository. A strict visual difference score was not computed across applications because their native window chrome, scaling, font rasterization, and available runtime data differ. New scan currently starts the existing scanner configuration directly; Burp's full scan-setup flow is not reproduced. Scanner cancellation updates task/UI state, but the active worker can continue until its current network operation finishes. Live native detach/reattach and narrow-window behavior need a cross-platform manual pass. BApp Store and AI are WIP as requested. See [local-tools evidence](burp-v2026.3.3-local-tools-evidence.md) for the Proxy/Repeater/Intruder implementation and its remaining gaps.
